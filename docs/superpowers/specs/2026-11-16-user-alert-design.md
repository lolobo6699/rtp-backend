# 個人異常推播 設計

## 目的
在原本「平台 RTP 推播」之外，新增「個人異常推播」：某用戶在某彩種的 RTP 與遊戲盈虧**同時**達到門檻，就推 TG。

## 已確認的決定
- 以**個人用戶**為單位，資料來自統計站「用户彩种分析查询」API（`POST /api/v1/user-lottery-analysis`）。
- 條件：RTP ≥ RTP 門檻 **且** 個人遊戲盈虧 ≥ 盈虧門檻（以「平台＋帳號＋彩種」一列為單位判斷）。
- 時段與原本相同（13:00、22:00、03:15），同時段可能收到兩則（平台＋個人）。兩者互不影響。
- 每個時段都重新判斷，仍超標就再推（不跨時段去重）；同一小時內只推一次（hour_key = `user-YYYY-MM-DD-HH`）。
- 彩種：可複選的下拉選單。API 沒有「彩類」，因此不做彩類。選項＝預設（奇趣腾讯分分彩、哈希分分彩）＋查詢時看過的彩種，另有「更新彩種清單」按鈕（查最近 30 天全部平台資料收集彩種名，逾時 240 秒；API 沒有彩種清單功能）。彩種名去掉括號代號後比對。
- 日期：今日／昨日／本週／當月（相對日期，預設今日）。API 為營業日（03:00 起算），03:15 時段照設定查、不特別處理。
- 查詢平台：與商戶清單同步，排除 XO（XO 不支援一次查全部會員）。
- 兩個門檻預設空白，由使用者自己填；未填或未啟用 → 不推播。
- 發到同一個 TG 群組；多個用戶合併成一則（每人一段），超過 4000 字才分則；訊息文字用簡體。
- 部分平台查詢失敗：照推，訊息最後加「⚠ 以下平台查询失败，未纳入：…」；沒人超標時也發這行提醒。全部平台失敗 → 視為失敗，撤銷 hour_key 讓下一次重試。
- 沒有任何人超標、也沒有平台失敗 → 不發訊息。

## 元件
| 檔案 | 職責 |
|---|---|
| `lib/user-source.js` | 呼叫 API、欄位轉換、錯誤分類（302 白名單、401 金鑰、400 參數、非 JSON、全部平台失敗） |
| `lib/user-alert.js` | 讀寫設定與彩種清單、驗證、日期換算、門檻判斷、組訊息、執行推播 |
| `lib/tg.js` | 發送 TG（遮 Token、逾時、錯誤展開、長訊息分則） |
| `api/user-alert.js` | 後台 API：讀設定、存設定、/lotteries 更新彩種清單、/preview 預覽、/test 測試推播 |
| `api/cron.js` | 平台推播與個人推播並行（Promise.allSettled），各自成功／失敗 |
| `public/index.html` | 「個人異常推播」設定區塊與預覽表 |

## API 對應
- 請求：`{ platforms, dateStart, dateEnd, account: '', byPlayType: false, profitMin }`（profitMin 帶盈虧門檻，讓 API 先過濾）。
- 欄位：`平台`→異常專案、`帐号`→用戶名稱、`彩种`（拆名稱與代號）、`投注金额`、`奖金`、`返点`、`盈亏`、`中奖率`、`RTP`（缺則 奖金÷投注金额）。排除 `system` 帳號。
- 逾時 120 秒，單次查詢（API 為即時查詢，不在同一時段內快速重試；靠排程 3 次重試）。

## 環境變數
- 網址與代理沿用 `STATS_API_URL`、`PROXY_URL`。
- 金鑰：`USER_STATS_API_KEY`（新 API 專用），沒設時沿用 `STATS_API_KEY`。
- 可選 `USER_STATS_API_URL` 覆寫完整網址。本機測試可設 `USER_STATS_MOCK=1` 用假資料。

## 設定儲存
`settings` 表：`user_alert`（設定 JSON）、`user_lottery_options`（彩種清單 JSON）。
