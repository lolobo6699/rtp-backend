# 個人異常推播 設計

## 目的
在原本「平台 RTP 推播」之外，新增「個人異常推播」：某用戶在某彩種的 RTP 與遊戲盈虧**同時**達到門檻，就推 TG。

## 已確認的決定
- 以**個人用戶**為單位；資料來自另一支新 API（尚未完成），先做畫面與流程，資料來源之後再接。
- 條件：RTP ≥ RTP 門檻 **且** 個人遊戲盈虧 ≥ 盈虧門檻。
- 時段與原本相同（13:00、22:00、03:15），同時段可能收到兩則（平台＋個人）。兩者互不影響。
- 每個時段都重新判斷，仍超標就再推（不跨時段去重）；同一小時內只推一次（hour_key = `user-YYYY-MM-DD-HH`）。
- 彩類單選（預設時時彩），彩種可複選（預設奇趣腾讯分分彩），每個用戶 × 彩種各自判斷。
- 日期：今日／昨日／本週／當月（相對日期，預設今日），排程每次換算成台灣時間日期。
- 兩個門檻預設空白，由使用者自己填；未填或未啟用 → 不推播。
- 發到同一個 TG 群組；沒有任何人超標時不發訊息。
- 多個用戶合併成一則（每人一段），超過 4000 字才分則；訊息文字用簡體。
- 彩類／彩種選項等新 API 串接後再換成 API 提供的清單。

## 元件
| 檔案 | 職責 |
|---|---|
| `lib/user-source.js` | 新 API 抓資料，轉成統一格式；未設定環境變數時回報「資料來源尚未設定」 |
| `lib/user-alert.js` | 讀寫設定、驗證、日期換算、門檻判斷、組訊息、執行推播 |
| `lib/tg.js` | 發送 TG（遮 Token、逾時、錯誤展開） |
| `api/user-alert.js` | 後台 API：讀設定、存設定、預覽、測試推播 |
| `api/cron.js` | 平台推播與個人推播並行，各自成功／失敗 |
| `public/index.html` | 新增「個人異常推播」設定區塊與預覽表 |

## 統一資料格式（user-source 輸出）
`{ project, username, lottery, lotteryCode, sales, payout, rebate, profit, winRate, rtp }`
- profit 缺 → payout + rebate − sales；rtp 缺 → (payout + rebate) / sales。

## 環境變數（新 API 接上時才設）
`USER_STATS_API_URL`、`USER_STATS_API_KEY`。本機測試可設 `USER_STATS_MOCK=1` 用假資料。

## 錯誤處理
- 未啟用／資料來源未設定 → 回傳 skipped，不算失敗。
- 抓資料或 TG 失敗 → 撤銷本小時 hour_key，讓同時段下一次排程重試；錯誤用 describeError 展開。
- TG 訊息超過 4000 字自動分則。
